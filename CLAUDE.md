# pipeOS — build repo

Diskless Alpine appliance for headless agent boxes. The root fs is tmpfs,
rebuilt every boot from the boot media (vfat `LABEL=PIPEOS`): apkovl for
config/state, local apk repos for software. `/work` (ext4 `LABEL=PIPEWORK`)
holds bulk data. Machine-scoped agent rules ship in
`overlay/root/.claude/CLAUDE.md`; this file is about working on the repo.

## Deployment model — every change lands twice

1. **Live box** (`/usr/local/bin`, `/etc`, …) — persists via lbu/pipeos-save.
   New files under `/etc/init.d` need a `+etc/init.d/<name>` line in
   `overlay/etc/apk/protected_paths.d/lbu.list` or they vanish at reboot
   (apk audit skips new files there).
2. **`overlay/`** — the identical file, committed, ships in future images.

Step 1 is `pipeos deploy-overlay [--from REF]` (operator; agent-fenced like
`pipeos save`), not a hand tarball: it installs a commit's overlay, refuses to
touch the per-box generated files (`etc/pipeos/*`, `root/.pipe/policy.json`),
saves, verifies, and stamps what it deployed in `/etc/pipeos/.overlay-stamp`.
That stamp is what makes "how old is this box's overlay?" answerable — before
it, #51/#62/#63/#71 sat merged and undeployed for four days on three boxes and
nothing on any box said so (pipeOS#97).

`pipeos status` reports the stamped commit and how far behind `origin/main` it
is; `pipeos-selfcheck` WARNs on any undeployed commit and goes CRITICAL past
`OVERLAY_CRIT_DAYS` (card, default 3). The older file-drift line is still
there but answers a weaker question — it compares against whatever branch the
local checkout is on. Runlevels are NOT in overlay/ — they're generated by
`scripts/40-build-apkovl.sh` (mk_runlevel lines); a live `rc-update add` must
be mirrored there.

## Build order

`make chroot` → `make apks` → (`make apkovl` →) `make image|usb|metal`.
`image` intentionally does NOT depend on the slow `apks` target;
`50-build-image.sh` refuses to build if `out/repo` is staler than
`aports/`/payloads (override: `FORCE=1`). After any package change run
`make apks` first. `overlay/etc/apk/world` is the single package list —
`scripts/30-build-apks.sh` derives its `UTILS` set from it.

## Two index formats — never mix the recipes

- `apks/pipeos` (custom packages): apk-**2** index — `abuild -r` writes and
  signs `APKINDEX.tar.gz` in the chroot. Re-index only via abuild/`apk index`
  + `abuild-sign` in the chroot.
- `apks/extra` (CDN closure): apk-**3** ADB index — `apk mkndx --sign-key`
  (see `extra-add`). The wrong recipe produces an index apk parses but whose
  packages fail install.

## The 2026-08-05 incident (why verification exists)

A hand-staged `out/media-stage/` dir — seeded from the *media* instead of
`out/repo` — put a stale hermes apk + mismatched re-signed APKINDEX on the
boot media. Boot-time reinstall then failed with "v2 package integrity
error" and the box came back without claude-code, silently. Rules that came
out of it:

- Never hand-copy apks to the media; use `pipeos sync-media` (verifies, swaps
  atomically, simulates, rolls back on failure).
- `scripts/verify-repo.sh` gates the image build's repo→media copy.
- No content-hash pins (`pkg><Q1…=`) in `/etc/apk/world` — any rebuild
  changes the blob and the pinned entry silently stops resolving at boot.
  `pipeos verify` warns when they creep in (plain `apk add pkg` writes them;
  rewrite to the bare name).
- On-box saves go through `pipeos save` (atomic; plain `lbu commit` has a
  power-loss window where no canonical apkovl exists on the media).

## Testing

- VM: `make vm` (NVMe attach) or `VARIANT=usb scripts/61-run-vm-usb.sh`;
  ssh -p 2222 root@localhost, password `pipeos`. Ctrl-a x quits the serial
  console. Rebuild the image after any VM session that committed state.
- Real boxes: `pipeos verify` must PASS before and after any media change;
  the reboot drill is `pipeos save` → reboot → boot-report DM says all green.
